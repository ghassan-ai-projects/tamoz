# Phase evidence and implementation review

This folder holds the committed evidence package and implementation-review record
for each phase in the plan. It is empty of results today because no production
code has been changed by the planning pass — each `phase-N/implementation-review.md`
is a template with status **not started** until that phase is implemented.

## What a completed phase must commit here

`phase-N/implementation-review.md` plus a manifest that binds every result to the
build that produced it:

- phase status and date; the git revision (and whether the tree had uncommitted
  changes);
- the Enola baseline receipt taken before editing and the post-change
  `diff_snapshot` / `compare_receipts` result;
- the exact test and quality-gate commands with their output digests and exit
  codes;
- the changed files (or an explicit no-change reason);
- generated-artifact digests, regenerated by their owning command — never
  hand-edited;
- known blind spots and environment limits (e.g. a sandbox that cannot bind
  `127.0.0.1` for the Telegram fixture server);
- a plain statement separating fixture/fake-transport plumbing evidence from
  real-provider/real-transport evidence.

## Review discipline (per phase)

Each phase runs the same loop before its review note is written, mirroring the
study's own review method (`../../08-review-log.md`):

1. **Plan critique** — challenge the phase file for missing seams, undefined
   failure states, cross-surface drift, and overclaims.
2. **Plan improvement** — tighten the phase's acceptance bar and work items around
   the critique.
3. **Implementation pass** — deliver the phase's work items against the named
   seams.
4. **Three reviews** — code quality, feature completeness, and gap-hunting.
5. **Repair pass** — fix what the reviews found before writing the review note.

No review result is ever treated as real-provider or usefulness evidence. A green
plumbing suite proves the machinery routes, fences, and projects correctly; it
does not prove the chat feels useful. That claim belongs to the benchmark.
