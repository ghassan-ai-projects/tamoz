## Findings

1. **P2 — ADR-004** (`documentation/adr/adr-004-explicit-tamoz-seq-no-native-proc.md:13`): the Decision states "`Tamoz.seq` is the canonical composition API; `Tamoz.step` adapts two-argument callables," but the symbols were not found in any plausible home: `gems/tamoz-core/lib/tamoz/core.rb` (read in full — no `seq`/`step`), `gems/tamoz-graph/lib/tamoz/graph.rb` (defines only `Tamoz.graph`), `gems/tamoz-core/lib/tamoz/seq.rb` and `.../composition.rb`/`.../pipeline.rb` (absent), no `gems/tamoz` meta-gem, no `test/seq_test.rb`. The ADR's own Verification line only claims `tamoz-chain` is absent — that holds (`gems/tamoz-chain/` does not exist). Fix direction: name the file where `Tamoz.seq`/`Tamoz.step` are defined in the Verification line, or Revise the ADR if the composition API was dropped/renamed. (Caveat: reviewer had no grep tooling; probes were targeted reads.)
2. **P3 — ADR-001** (`adr-001-...md:26`): "all 27 gems" — the root README gem table now lists 29 `tamoz-*` gems. Dated-evidence count drift; namespace/prefix claim itself holds.
3. **P3 — ADR-005** (`adr-005-...md:23`): Verification says the `Executor` "wraps each node in the matching `catch`". In the code, the throw originates in `InterruptCursor#call` (`gems/tamoz-graph/lib/tamoz/graph/interrupt.rb:37`, tag `:tamoz_interrupt`) and the matching `catch` is in `Tamoz::Pool::Base#execute` (`gems/tamoz-concurrency/lib/tamoz/pool.rb:82`); the executor only classifies `TaskResult::Interrupted`. Mechanism exactly as decided (throw, not exception; worker-scoped); only the location credit is imprecise.
4. **P3 — ADR-007** (`adr-007-...md:21`): "`Tamoz::Core.deep_freeze` … (enola: 34 dependents)" — symbol verified (`gems/tamoz-core/lib/tamoz/core.rb:160`, recursive freeze, raises on unsupported), but the fan-in count is a snapshot artifact a reader cannot open.
5. **P2 — ADR-008** (`adr-008-threads-is-the-default-pool-inline-in-tests.md:12-14`): the Decision body claims "`:inline` is the deterministic debug/test default; `:fibers` requires `async`, lazily. All three are observationally equivalent by conformance test." The code has exactly two modes — `Configuration::CONCURRENCY_MODES = %i[inline threads]` (`gems/tamoz-core/lib/tamoz/configuration.rb:5`) and `Tamoz::Pool.for(:fibers)` raises "fiber pool is unsupported until its conformance suite passes" (`gems/tamoz-concurrency/lib/tamoz/pool.rb:35-36`). The title rule still holds (`concurrency: :threads` default, configuration.rb:13-14), so only the equivalence/three-pool clause is stale. Fix: Revise the body to two pools + refused fibers.
6. **P1 — ADR-010** (`adr-010-ruby-3-3-floor-3-4-and-4-0-primary-targets.md:22`): Verification states "CI matrix = `["3.3", "3.4", "4.0"]` (`.github/workflows/ci.yml`), matching this ADR exactly." Today's `.github/workflows/ci.yml:24-38` has a single `test` job running `ruby-version: .ruby-version` (3.3.11) — no version matrix. The Decision's own clause "CI covers MRI 3.3, 3.4, 4.0" (adr-010:12) is therefore not true of today's CI either (A4-adjacent). The floor itself (`.ruby-version` = 3.3.11) holds. Fix: either restore the matrix or Revise the Decision + Verification to the single-pinned-version reality.
7. **P2 — ADR-009** (`adr-009-the-model-request-prefix-is-byte-stable-within-a-cache-epoch.md:24`): "enforced by the conformance suite in `gems/tamoz-evals`" — `gems/tamoz-evals/README.md` scopes that gem to "canonical artifacts, schemas, digests, the verifier" (harnesses/suites live in `tamoz-evals-runner` / root `test/`). Invariant 16 itself exists and matches (`docs/design-v0.1/INVARIANTS.md:42`, "Stable model prefix per cache epoch"). Fix: point the Verification line at the actual suite path.
8. **P2 — ADR-024** (`adr-024-smart-means-evidence-based-proportional-and-verified.md:29`): "The dimensions are measured by `gems/tamoz-evals` (success, calibration, …)" — same evals/evals-runner confusion ADR-025 explicitly resolved: executable measurement runtime lives in `tamoz-evals-runner` ("evaluation harnesses, scorecards, treatments"), while `tamoz-evals` is artifacts/schemas/verifier. 9. **P1 — ADR-033 + ADR-034** (`adr-033-...md:17,31` and `adr-034-...md:29`): both pin skills code to `gems/tamoz-agent-capabilities` — ADR-033's note says "skill *sourcing* now lives in `tamoz-agent-capabilities` (ADR-052)" and its Verification says "Portable `SKILL.md` sourcing is in `gems/tamoz-agent-capabilities`"; ADR-034's Verification says "Skill tree-digest identity and staged activation are in `gems/tamoz-agent-capabilities`." Fix: repoint the ADR-033/034 verification lines to `tamoz-tools`/`tamoz-agent-kernel` (or wherever staged activation lives post-ADR-052) and reconcile the root README row with the gem README.

11. **P2 — ADR-048** (`adr-048-tamoz-owns-the-model-boundary-one-digest-bound-openai-compatible-transport.md:32`): Verification names `Tamoz::Agent::ModelClientFactory`; the symbol was not found by targeted reads (gems/tamoz-agent-kernel/lib/tamoz/agent/kernel/ entry dir — no `model_client_factory.rb`; gems/tamoz-agent/lib/tamoz/agent/ — none; neither kernel nor agent facade README names it).
