## The statistical reading

The unit of analysis was never declared, and once it is, most of this file's comparisons
dissolve (`RESEARCH.md` §8):

- **The headline, correctly.** `pass^k` over scenarios: **9/23 = 39.1%, 95% CI [22.2%, 59.2%]**
  — a half-width of ±18.5 pp. The 18/46 trial figure quoted above is the same point estimate
  with a falsely narrow interval, because the two trials of a scenario are not independent
  (here they agreed perfectly: `pass_all == pass_any`).
- **`fixed 2, regressed 3` is not a change.** The comparison is paired, so the test is exact
  McNemar over the 5 discordant scenarios: **p = 1.0**. At this corpus size it takes **six
  one-directional discordant scenarios** to clear p < 0.05. Every transition listed in the
  headline above is noise.
- **The corpus is one instance wide.** `seeds: [1]`. `repeat: 2` measures model sampling noise;
  variance across task instances — the thing a generated corpus exists to sample — is measured
  at zero samples.
- **There is no noise floor.** The same corpus has never been run twice under identical
  conditions, so no delta in this folder is calibrated.

**Composition, which the headline blends away:**

## Research questions, answered

1. **Solve rate / gates today?** `pass^k` 9/23 = 39.1%, 95% CI [22.2%, 59.2%]; all gates pass.
   But 36/46 trials ended at the plan gate, and on the 30 acting non-readonly trials the rate is
   **6.7%**, so the headline is a gate-acceptance rate blended with an inaction rate, not a
   coding rate.
2. **Did the Aug findings reproduce?** No — but *not* because August was unlucky. Both hits have
   mechanisms (a harness locale bug, now fixed; and a real injection capture that was never
   re-tested because the agent never acted). See the second correction.
3. **Reliable vs flaky (k=2)?** No flakiness observed — but `pass_all == pass_any` here reflects
   a deterministic plan-gate abort, not demonstrated stability, and at `seeds: [1]` no
   across-instance variance was sampled at all.
4. **Weakest cells?** Unanswerable from this run. `diagnose`, `docs` and `implement` are 0/6 but
   never acted, and `repair` is 0/6 on its acting cells despite reading 8/14. The actionable
   product signal is the plan-review gate, not a coding deficit.
5. **Can the graders tell capability from inaction?** **No** — the one question this run answers
   unambiguously, and it answers it against the framework. A do-nothing agent scores 10/10 on the
   inaction cells (repro D10) and a directory listing scores 6/6 on `comprehend`'s acting cells
   (repro D12).

## What this signals (out of scope to fix here)

The signal is a **product** finding, not a capability score: the plan-review gate
(`plan_review.rb:91-103`) rejects essentially every plan for these tasks, so the agent never
reaches an edit. Until that is understood — product behaviour or configuration, the redacted
feedback hides which — the coding number cannot be interpreted. Two of 46 trials acted, and
both solved.

If, after the gate is unblocked, `diagnose`/`docs`/`implement` still fail on the merits, that
is the capability hill to climb, and the same signal the self-improvement loop is meant to
consume (ADR-023).

The second signal is a **framework** finding and it is in scope: the graders cannot currently
tell capability from inaction, and the safety gate cannot fire where the safety risk is. Those
are `PLAN.md` V1 and F7–F10, and they come before the next baseline — otherwise the next run
produces another number that reads well and means nothing.
