# Phase 1 plan — `tamoz-mcp-websearch`

## Intent

Package the already-isolated operator-side websearch adapter as a separate
gem. This is a boundary and packaging change, not an egress-policy redesign.

## Source and consumer map

Move these four files together:

- `gems/tamoz-mcp/lib/tamoz/mcp/websearch.rb`
- `gems/tamoz-mcp/lib/tamoz/mcp/websearch/egress_policy.rb`
- `gems/tamoz-mcp/lib/tamoz/mcp/websearch/egress_client.rb`
- `gems/tamoz-mcp/lib/tamoz/mcp/websearch/egress_circuit.rb`

Update the actual consumers and package surfaces:

- `script/websearch_adapter`
- root `Gemfile` and `Gemfile.lock`
- the test helper's gem inventory/load paths
- dependency-isolation, packaging, public-API, documentation, and dependency
  review surfaces that enumerate gems
- root/component documentation where the old `tamoz-mcp` ownership is stated

The eval harness directly requires the websearch adapter in
`gems/tamoz-evals/lib/tamoz/evals/harness/agent_smoke_corpus.rb`; its lockstep
runtime dependency on `tamoz-mcp-websearch` is therefore intentional and must
remain visible in the gemspec, lockfile, package inventory, and release docs.

## Proposed dependency direction

`tamoz-mcp-websearch` depends exactly on `tamoz-mcp` and `tamoz-core`, both at
the repository's lockstep version. The moved code directly reads Core secret
patterns and uses MCP errors, canonical JSON, and budget contracts. No parent
MCP, agent, CLI, or eval dependency may point back to the new gem. The
namespace remains `Tamoz::Mcp::Websearch`; no alias is added in the old gem.

The package owns `Tamoz::Mcp::Websearch::VERSION` and the moved public surface.
The entrypoint remains `tamoz/mcp/websearch`, preserves the current require
order (`tamoz/mcp` followed by the three support files), and does not change
the parent MCP umbrella beyond removing the moved files. A clean process has
already confirmed that `require "tamoz/mcp"` does not load websearch, `net/http`,
or `resolv`; the implementation must preserve that fact.

## Ordered work

1. Record the current file/require/dependency/package baseline and inspect the
   public constants and test contracts.
2. Freeze the gem entrypoint/version, exact dependency closure, public API
   ownership, and whether an eval dependency exists from the two plan reviews.
3. Create the new gem skeleton and move the four files as one cohesive unit.
4. Update package metadata, operator/eval consumers, inventories, and docs.
5. Add boundary tests for parent load isolation and installed new-gem loading;
   move existing websearch test ownership without weakening assertions. The
   contract matrix must retain error ancestry/safe messages, Result fields and
   truncation, per-hop pinning, redirect/credential rules, circuit conditions
   and operator reset, egress binding/resume rejection, and injection
   containment. Fixture-backed eval evidence remains plumbing evidence, not
   real-provider intelligence evidence.
6. Regenerate generated dependency/public/requirements artifacts in their
   documented order, then run focused tests and static gates.
7. Run five independent read-only reviews with these disjoint lenses:
   security/egress; authority/error contracts; package/load isolation;
   operator/eval behavior; documentation/API. Each returns PASS/FAIL, severity,
   paths/lines, and exact required fixes. Send all findings back to the same
   implementation agent, re-run the bar, and commit only after reviewer PASS.

## Review questions for planning

The plan-review decision is now: direct dependencies are `tamoz-mcp` and
`tamoz-core`; public ownership is the new package; the direct eval consumer is
retained as an explicit lockstep dependency; and the installed proof must remove
repository load paths/RUBYLIB, test parent-only and child-closure subprocesses,
and exercise the operator gate. Generated dependency review and requirements
artifacts must be regenerated by their scripts, not hand-edited.

The phase bar is met. All five final read-only review lanes returned PASS after
the correction loop. The remaining audit gaps are pre-existing documented
