# M3 — Durable SQLite runtime

Status: implemented and deep-reviewed for the v0.1 alpha foundation.

M3 turns the deterministic M2 graph runtime into a recoverable local runtime without
introducing a second planner or executor. The same graph definition, reducer, barrier,
interrupt, subgraph, and stream semantics run against either the in-memory checkpointer or
the SQLite adapter.

## Delivered contracts

- Definition-bound, versioned, canonical checkpoint encoding with digest and size checks.
- Secure SQLite files, checked migrations, WAL with `synchronous=FULL`, bounded connection
  pooling, bounded transaction retry, integrity checks, and fork fail-closed behavior.
- Per-namespace leases with backend-time expiry and monotonically increasing fences.
- Task outcomes committed before coordinator delivery and reused after process death.
- Durable FIFO requests for turn, resume, retry, continue, fork, and redirect.
- Redirect target execution and cancellation generation pinned once before execution.
- Effect prepare/start/complete protocol with append-only attempts, explicit safety classes,
  unsafe ambiguity, late receipts, and authorized human resolution.
- Exact compare-and-set Store with append-only versions, bounded byte-ordered iteration, and
  opt-in external protection for sensitive values.
- SQLite online backup with secure atomic publication and destination verification.
- Conservative checkpoint pruning, compare-protected thread tombstones, retention, atomic
  purge, and retained deletion receipts.

## Minimal use

```ruby
adapter = Tamoz::SQLite::Adapter.new(path: "/private/runtime/tamoz.sqlite3")
app = definition.compile(checkpointer: adapter)
runner = app.durable_runner

request = runner.deliver(
  {"message" => "hello"},
  thread: "thread-1",
  request_id: "request-1"
)

adapter.close
```

Public graph mutation methods intentionally reject a durable adapter. All durable mutation
goes through `DurableRunner`, which owns request identity, execution binding, recovery, and
terminal transitions.

## Guarantee boundary

M3 provides at-least-once request delivery with one durable execution binding. It does not
claim exactly-once external effects. An effect can be exactly identified and its receipts
retained, but a process can die after target I/O and before recording the result. Safety
class and reconciliation policy decide what happens next; `unsafe` stops at `unknown`.

SQLite is a single-host durability backend. Scheduling, MCP transport, skills, model calls,
semantic Store search, multi-host consensus, and streaming input admission remain later
milestones.

## Verification

The committed gate covers:

- canonical codec round trips and corrupt/oversized input rejection;
- memory-checkpointer regression equivalence;
- migration rollback/checksum, permissions, symlink, pool, fork, and integrity behavior;
- lease fencing, stale writers, durable pending writes, and restart recovery;
- request duplicate/FIFO/recovery plus all six operations, including fork and redirect;
- every effect ambiguity class, late receipts, retry rules, and human resolution;
- Store CAS, namespaces, prefix order, protection, cursors, and every transaction fault hook;
- online backup publication/restore and tombstone/purge receipt behavior;
- real `SIGKILL` immediately before and after checkpoint commit;
- real `SIGKILL` after task-write commit, proving the node is not re-executed;
- a real two-process lease race proving one live fence;
- complete M0–M2 tests, design validation, syntax, packaging, and dependency isolation.
