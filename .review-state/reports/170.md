  (identical raise set AND identical return value: both return the arguments hash). Two names

  grep (incl. send/__send__/public_send patterns via plain grep over all *.rb) shows no other

  Behavior-preserving by inspection. APPLY.
- C2 — rename `adapter_reason` → something like `build_reason_payload`: it returns a frozen
  single-key hash, not a reason string. REJECT — marginal gain; the name already reads as "the
  adapter-derived reason record", and a rename on the egress-authority surface for a nuance is
  churn.
- C3 — consolidate `validate_url!` with `validate_location_url`/`validate_location_host`
  (shared HTTPS + allowlist logic). REJECT — error bytes are pinned and intentionally distinct
  ('browser permits HTTPS URLs only' vs 'browser adapter final URL must use HTTPS', different

  plus argument-url vs final-location are authority-distinct paths. Keep explicit.
- C4 — `outcome_fields_for`'s else-raise is unreachable from `execute` (adapter_status's return
  domain is exactly :succeeded/:failed/:unknown/:denied/:interrupt). REJECT removal —
  `build_outcome` is public API and can be called directly with any status symbol; the guard is
  its contract, not dead code.
- C5 — `build_outcome` is public but has no external caller. REJECT visibility change —
  public/cross-gem API is untouchable per brief.
- C6 — line-broken modifier style at L69–70. REJECT — rubocop-clean already; style churn.
