### Candidates

- C1 — DELETE duplicate document-path twins by routing through the existing
  tolerant helpers: `select_matching_documents` → `correlation_matches?`
  (deleting `document_correlation_matches?`), `from_documents` → `trace_id_from`
  (deleting `trace_id_from_document_correlation`).
  Proof of equivalence for string-keyed correlations: `fetch(:thread_id, h['thread_id'])`
  ≡ `h['thread_id']` when no `:thread_id` symbol key exists; document correlations come
  only from `Journal.read` → `JSON.parse(line)` (recorders.rb:446) or hash literals —
  string keys by construction, so the symbol branch never fires and both twins reduce
  to the shared one. Repo-wide grep incl. send/__send__/public_send: both deleted names
  are referenced ONLY in trace.rb. KEEP `first_complete_document_correlation`: its
  predicate (BOTH ids present) differs from `first_populated_correlation`'s (`any?`);
  unifying would change which correlation anchors the trace id.
  Confidence: high.
- C2 — `span_from`: hoist `return unless trace_id` above
  `document = document_from(signal)`. Guard-first step-down; skips pointless `to_h`
  work whenever no complete correlation exists. `document_from` is pure
  (`respond_to?(:to_h) ? to_h : itself`), result discarded on early return → provably
  behavior-preserving. Confidence: high.
- C3 — REJECTED: unify `first_populated_correlation` with
  `first_complete_document_correlation`. Not equivalent (`any?` vs both-ids): with a
  first correlation holding only `thread_id`, populated yields trace_id nil while
  complete finds a later full correlation. Behavior change.
- C4 — REJECTED: rename `span_from`/`document_from` to `build_*` vocabulary.
  X_from_y converters don't collide with any existing verb spelling (§3.1's rule is
  against second spellings); single-caller privates; rename churn without searchability
  gain.
- C5 — REJECTED: make `first_populated_correlation`'s bare `signal.fetch('correlation')`
  default to `{}` like `signal_correlation` does. Changes bytes on an error path
  (KeyError) for hash-like signals lacking `correlation` under nil filters; covers a
  rare case preemptively — owner directive forbids.
- C6 — REJECTED: inline single-use wrappers (`span_attributes`, `span_anchor`,
  `document_from`). They name intent at call sites; inlining is style churn.
- C7 — REJECTED: drop `.lazy` in `first_populated_correlation` (arrays here). Micro-perf
  churn, zero readability gain.
