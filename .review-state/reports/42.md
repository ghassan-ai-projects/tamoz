## Candidate list (Phase 1, written before any edit decision)

- **C1** — `encode_registered` rescue list `rescue Error, ConfigurationError, InvalidUpdateError`
  looks like redundant enumeration. **REJECTED**: it is load-bearing. Per
  `gems/tamoz-core/lib/tamoz/error.rb`, `ConfigurationError` (L217) and `InvalidUpdateError`
  (L235) inherit **directly from StandardError**, not from `Tamoz::Error`; only
  `UnsupportedValueError/SensitiveValueError/StateLimitError` sit under `InvalidUpdateError`.
  Narrowing to `rescue Error` would wrap configuration/invalid-update failures raised by a
  registered encoder into a rewritten `InvalidUpdateError` message — an error-identity change,
  which is product for this codec.
- **C2** — `Registration#initialize(encode: true)` is a §4 boolean kwarg. **REJECTED**: public
  cross-gem API (`StateCodec::Registration` appears in `test/public_api_test.rb` L204); callers
  exist in `test/core_state_codec_test.rb` (`encode: false`, legacy-decoder lane) and the codec
  is consumed across tamoz-graph/sqlite/agent/agent-memory/agent-cli/evals. API is untouchable.
- **C3** — merge near-duplicate `count_items!` / `count_items_for_load!`. **REJECTED**: their
  only difference IS the contract — dump-phase raises `StateLimitError`, load-phase raises
  `CheckpointCorruptionError`. Unifying needs an error-class parameter: more machinery, less
  clarity at a durability boundary.
- **C4** — remove seemingly dead `if object_id` guard in `encode_container`'s ensure.
  **REJECTED**: cannot personally prove byte-neutrality in the strict sense. If a registered
  class overrode `object_id` to return nil, today's code leaves a stale `nil` key in the
  cycle-tracking hash while the edited code would delete it — an observable difference in that
  corner. The bar is proof, so it stays.
- **C5** — pass-through rescue in `load` (`rescue CheckpointVersionError, CheckpointCorruptionError;
  raise`) is technically redundant since the fallback rescue only catches JSON parse errors.
  **REJECTED**: it documents the non-wrapping invariant alongside its load-bearing twin in
  `encode_registered`; removal is churn against the file's deliberate defensive symmetry.
- **C6** — brace/do-end block inconsistency (L89–92), `[true, false].include?(...)` rewrite
  (L260), `state.fetch(:active)` vs `state[:active]`. **REJECTED**: pure style churn.

The long methods (`Registration#initialize`, `encode_node`, `validate_node!`) are flat
guard-chains / tag-dispatch case statements already decomposed where it pays
(`validate_array_node!`, `validate_object_node!`, `validate_registered_node!`). Recorded wire-codec
cohesion exception applies: no extraction proposed. Naming follows §3 vocabulary throughout
(`encode_`/`decode_`/`validate_`/`require_shape!`/`bounded_integer!`, predicate `encode?`).
