# Tamoz roadmap

Tamoz is a Ruby-native durable agent framework, currently at `0.1.0.alpha.1`
(pre-release). This page says what has shipped, what is in progress, and where
the public contract is still moving.

## Shipped

- **The reviewed change loop** — plan, review, approval, verified effect, and
  bounded repair. Nothing acts without a reviewed plan; no file changes without
  an approval for that exact diff.
- **Durable sessions** — threads survive crashes and resume from their last
  committed barrier instead of guessing.
- **Trusted profiles** — project authority pinned outside the repository, with
  named checks, budgets, and policy digests.
- **The sealed capability host** — four closed-world built-in sources (tools,
  skills, MCP servers, websearch) pinned at session construction.
- **Three-layer memory** — experience, knowledge, and wisdom, with deletion and
  provenance safety.
- **Bounded self-healing (DR-2)** — typed recovery on a durable circuit, with
  rollback and human gates.
- **Durable scheduling** — `at` and `interval` occurrences in `tamoz-scheduler`,
  with misfire, overlap, and budget enforcement.
- **The supervised episode worker** — a gRPC-contracted worker in `tamoz-stream`
  that executes one sealed Situation snapshot per episode.
- **Telegram as an operator channel** — with evidence-gated approval (ADR-049).
  Every effect requires filesystem-operator evidence, so the channel is
  deny-only in practice.
- **Evaluation and release-evidence machinery** — every release claim is machine
  evidence, regenerated by running the named tests.
- **Quality ratchets** — Reek, SimpleCov, and Enola gates that fail rather than
  let the committed baselines grow.

## In progress

- **The autonomy milestone** — connecting the shipped primitives into one
  reliable unattended workflow: trigger → durable inbox → trusted authority →
  deliberation → governed capabilities → bounded execution → durable outcome →
  notification or approval request.
- **Observability completion** — the signal catalog and local journal are
  shipped; the full telemetry contract is still being closed.
- **UX / latency work** — deterministic channel behavior and the
  operator-facing latency surface.
- **Quality program slices** — extraction and characterization work continues
  against the committed baselines.

## Planned / partial

Everything that does not yet work, and the boundaries you should plan around,
is listed honestly in [limitations.md](limitations.md). The page is bound to
the measured release audit, so it cannot fall silently behind the product. Read
it before building on Tamoz.

## Open product questions

These are not ADRs — they are unresolved product choices (migrated here when the v0.1
`DECISIONS.md` archive's ADR record moved to the [ADR catalog](adr/README.md)).

- **Q1 — What physical environment should Tamoz Agent supervise first?** The v0.1
  durable-runtime proof assumes a coding agent; the first post-v0.1 milestone is
  physical-world supervision through `tamoz-stream` (ADR-035/036/038/039), but the concrete
  source and hazard model are open: home/environment monitoring, equipment health,
  inventory/location, or another domain. Naming the environment, read-only source, desired
  outcome, existing controller/interlocks, and accountable operator selects the first
  connector, SituationSpec, protected evaluation set, and deployment safety review. This is
  also entangled with the two-repo authority split (ADR audit open item O1 / candidate
  ADR-055).
- **Q2 — How finished should the research report be?** Chapters 5–8 of the source study were
  never written as report prose; this repository delivers their content as design docs.
  Producing a polished report/`.docx` is separate work, worth doing only if it has an
  audience beyond the owner.

## Release posture

Tamoz is pre-release. `0.1.0.alpha.1` is the first public line, and:

- **Stable:** the safety model — the reviewed change loop, approval for exact
  diffs, the sealed capability host, and no arbitrary shell.
- **Evolving:** the CLI surface, the documentation set, and parts of the
  contract named in [limitations.md](limitations.md) as incomplete.
- **Breaking changes** are announced in [CHANGELOG.md](../CHANGELOG.md) as the
  line moves toward a stable release.

For the current contract, see the [ADR index](adr/README.md). For the
contributor quality bar, see [governance/quality.md](governance/quality.md).
To try it, start with [getting-started/install.md](getting-started/install.md).
