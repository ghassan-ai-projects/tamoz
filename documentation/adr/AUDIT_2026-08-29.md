# ADR deep audit — 2026-08-29

Auditor pass over the entire Tamoz architecture-decision corpus, graded against
[`ADR_QUALITY_BAR.md`](./ADR_QUALITY_BAR.md). This document is the findings, the per-ADR
scorecard, the remediation, and the loop that drives the corpus to the bar.

**Scope.** ADR-001 … ADR-049 (the 48 sections of `docs/design-v0.1/DECISIONS.md` plus the
standalone ADR-049), the observability phase-5 decision mislabeled "ADR-048," the orphaned
approval-isolation ADR under `docs/approval-policy-redesign-2026-08-22/`, and the catalog in
`documentation/adr/README.md`.

**Method.** Each decision was read, assigned a tier, and checked against the shipped code —
not just against its own prose. Reality checks used the gem tree, `grep` over the runtime
source, and an [enola](../../.enola) architecture snapshot (13,405 facts, 60 insights) taken
at audit time. Evidence is cited inline so every verdict is reproducible.

**End goal (restated).** Not ADRs for their own sake — a decision record a security
reviewer or a new maintainer can trust *on its own*, because it is correct against today's
code, honest about what died, and complete about what shipped. See
[`ADR_QUALITY_BAR.md` §0](./ADR_QUALITY_BAR.md#0-end-goal--why-this-bar-exists).

## 1. Executive summary

The corpus is **substantively strong but structurally broken and materially stale.** The
individual decisions are unusually well-reasoned (ADR-049 is genuinely reference-grade). But
as a *system of record* it fails the bar on integrity and reality-consistency:

| # | Headline defect | Class | Evidence |
|---|---|---|---|
| 1 | **Two different decisions both numbered ADR-048** — "digest-bound model transport" (accepted) and "automated responses act only on durable evidence" (proposed, observability phase 5) | Not-clean / integrity (A1) | `DECISIONS.md:469` vs `docs/OBSERVABILITY_DESIGN.md:1098`; both listed under 048 in `README.md:62-63` |
| 2 | **"Four v0.1 runtime gems" is false** — the tree ships **27** `tamoz-*` gems, including an 8-gem decomposition of `tamoz-agent` that has no ADR | Wrong + Missing (A4) | `ls gems/` → 27; ADR-002 says four |
| 3 | **RubyLLM was fully removed** from the runtime, but ADR-002/003/004 and the design docs still frame the whole stack "over `ruby_llm`" | Wrong / obsolete (A4) | 0 refs to `ruby_llm`/`RubyLLM::` in any gemspec or `.rb`; GOAL.md still says "over `ruby_llm`" |
| 4 | **The capability catalog has four sources, not three** — `websearch` shipped as a first-class source; ADR-030 names only local tools, MCP, skills | Wrong (A4) | `gems/tamoz-agent-capabilities`, `gems/tamoz-mcp-websearch`; product.md already says four |
| 5 | **A real, implemented ADR is uncataloged** — "Isolate approval policy into `tamoz-approval`" has full ADR structure, status *implemented*, but no number and no index entry | Missing / orphan (A2) | `docs/approval-policy-redesign-2026-08-22/03-redesign-adr.md`; gem `gems/tamoz-approval` exists |
| 6 | **The authoritative text lives in an "archive."** The source of truth for ADR-001..048 is `docs/design-v0.1/DECISIONS.md`, whose own folder README says "Historical archive." The catalog that operators read links *into* a file marked historical | Not-clean (A2/A3) | `docs/design-v0.1/README.md:1` |
| 7 | **"Post-v0.1 / deferred" timing is stale** on ADR-012, 029, 031, 035 — MCP, scheduling, and streaming all shipped as gems | Obsolete (A4, minor) | `gems/tamoz-mcp`, `-scheduler`, `-stream` all present |
| 8 | **Tier-F decisions recorded as one terse paragraph** — ADR-022 (reviewed-plan gate) and ADR-023 (self-improvement) are the safety spine of the product yet lack the invariant linkage / threat model / change-bar the bar requires at their tier | Weak (E4/E5/E6) | `DECISIONS.md:181,195` |

None of these are cosmetic. #1 means a cross-reference to "ADR-048" is ambiguous. #2–#4 mean
the record actively misstates the shipped architecture — the single worst failure for a
safety product's audit trail. #5 means a shipped boundary change is undocumented in the
catalog. Together they are why this audit's first job is integrity, not prose polish.

## 5. Open items requiring owner input (honest gaps, not authored blind)

- **O1 — Two-repo authority split.** Project memory records a `tamoz` (Ruby judgment worker)
  + `agentic-stream` (Go authority) architecture. That is an architecturally significant
  decision that today has no ADR, and it sits in tension with ADR-040 ("one monorepo"). The
  Go repo is not in this tree, so authoring the ADR here would fabricate its content. **Needs
  the owner to confirm the split and its boundary so an ADR-055 can be written from fact.**
- **O2 — Trademark/RubyGems reservation** (ADR-001's own open action): is the name reserved?
  If done, add to ADR-001 Verification; if not, it stays an open pre-release action.
- **O3 — `tamoz-evals-runner`** is a second evaluation gem alongside `tamoz-evals`; confirm
  whether that split warrants a note on ADR-025 or is purely a packaging detail.
